# 实验计划：预算、并发、判据

## 预算（单卡 H100 串行）

| 阶段 | 内容 | 规模 | 估计 |
|---|---|---|---|
| 0 | 正确性 + 冒烟 | 微型模型 | < 1 min |
| A | 逐层异质性诊断 | d=256·L4，300 步 × 3 个 batch size | ~5 min |
| B1 | 扫参 | d=384·L6，15M tokens × 19 runs | ~15 min |
| B2 | 主实验 | d=512·L8，150M tokens × 5 arms × 3 seeds | ~100 min |
| B3 | 迁移 | d=320·L10，60M tokens × 5 arms × 2 seeds + 重调 | ~30 min |
| C | RLVR | Qwen3-0.6B + GSM8K，250 步 × 3 arms × 3 seeds | ~110 min |
| | | **合计** | **≈ 4.5 GPU·h（上限 8）** |

估算依据（FLOPs，`6·N·T`）：
- B2 单 run：`6 × 53M × 150M ≈ 4.8e16` FLOP，按 120 TFLOPS 有效吞吐 ≈ 400 s；
- C2 单 run：每步生成 48 条 × ~190 token + 反向，约 2 s/步（Newton–Schulz 约占 50% 额外计算）。

**并发数：1**（notebook 内串行）。Notebook 单次连接上限 1 小时 → 实际分 4–5 次连接；
每个配置完成即落盘 JSON，重跑自动跳过。
可选加速：notebook 末尾的 cell 能生成逐 seed 独立的 sbatch 脚本，4 路并发可把墙钟压到 ~2 小时
（占用 4 张卡，个人额度 48 张，无压力）。

## 判据（事先登记）

| 编号 | 判据 | 不成立意味着 |
|---|---|---|
| C1 | 固定步长 Muon 下，逐层 `‖ΔH_l‖/‖H_l‖` 的跨层 CV ≥ 0.3 且 p90/p10 ≥ 2.5，或时间维度 CV ≥ 0.15 | 前提太弱 → **no-go** |
| C2 | 相对 tuned Muon：≤ −0.5σ 为正向；±1σ 内为中性；明显更差为负向 | 中性可接受，负向需 C3/C4 补救 |
| C3 | 迁移惩罚比 = (intent_l 迁移 gap) / (fixed 迁移 gap) < 0.5 | 迁移性是主理论动机，不成立则故事塌一半 |
| C4 | `realized_gain / pred_gain` 中位数 ∈ [0.5, 1.5]；且 RL 准确率 ≥ tuned AdamW − 3pt | Muon 在 RLVR 的失效可能是谱形状，不是步长 |

**决策树**

```
C1 不成立 ────────────────────────────────► no-go，换题
C1 成立
 ├─ C3 成立 ───────────────────────────────► GO（主线 = 迁移性/少调参）
 ├─ C2 正向 ───────────────────────────────► GO（主线 = 效率）
 ├─ C4 救回 Muon ──────────────────────────► GO（主线 = RLVR 可用化）
 └─ 其余 ─────────────────────────────────► 有条件 go：转理论（一阶近似何时失效）
```

## 已知的局限（写报告时必须交代）

1. **3 个 seed 偏少**，只做趋势判断，不做显著性宣称。
2. **模型 ≤ 53M 参数**，优化器排序在小规模上未必外推（优化器文献里这已是共识，
   故同时报告 update-to-param 类的功能空间指标，而不是只报 loss）。
3. **RL 用 GRPO-lite 单步更新**（无 PPO 多轮 clip），结论限定在"单步策略梯度"内。
4. **KL 臂的 ε 是绝对量（nats/token/步）**，量级依赖词表大小与归约方式，
   所以跨模型规模迁移不如 activation 臂——这是它相对 `intent_act` 的一处真实退步。
   日程乘在 ε 上（α ∝ √ε），不用 cosine 会让收敛后步长停在非零水平。
5. **只对隐藏层矩阵用 Muon**，embedding/head 走 AdamW（Moonlight 做法），
   所以 embedding 占比高的模型上，效果会被稀释——这既是设定也是可讨论的变量。
6. **`‖X_l U_lᵀ‖_F` 用 512 token 子采样估计**（相对误差 ~4%），带一点每步随机性；
   它等价于给步长加了一个良性抖动，但也意味着 η 不是被"精确"复现。

## 2026-11-20 修订：六臂消融阶梯

原计划的 `intent_l` / `intent_t` 被重构为 6 个 arm，构成只改一个变量的阶梯：

| arm | 内部 mode | 新增变量 |
|---|---|---|
| `adamw` | — | 参照锚点 |
| `muon` | `fixed` | 基线 |
| `orscale` | `orscale` | 参数空间逐层 |
| `intent_act` | `intent_l` | activation 逐层 |
| `intent_kl_global` | `ext` | KL 目标、全局配额 |
| `intent_kl_layer` | `ext` | KL 目标、逐层分配 |

**实测发现（Stage 0）：逐层 KL 目标不可加。** 各层按 ε/L 调好后，联合更新的 KL 是目标的
3.4 倍——所有层沿同一下降方向移动，logits 变化同向叠加。已加入割线法校准，
实测残差 < 1%（0.995）。这条如果不处理，KL 臂的实际步长会比声称的大 3 倍以上。

**预算变化**：4.5 h → 2.8 h（B2 降到 100M tokens × 2 seeds，去掉默认 RL 与迁移阶段）。

## 2026-11-21 排查：`intent_act` 在 η≥0.05 时 NaN

**结论：NaN 本身是真实发散，不是崩溃；但代码里有两处缺陷让它变得难以诊断，已修复。**

1. **真实原因**：`intent_act` 的 η 是**每个矩阵**的相对输出变化预算。一个 block 有 7 个
   Muon 矩阵，其中 `wo` 与 `w_down` 直接写进残差流。所以 η=0.05 在 block 级别上远不止 5%，
   在 d=384×L6 上训练几百步后发散。实测 η=0.02 稳定、η=0.05 发散。
   → 扫参范围改成 `[0.005, 0.01, 0.02, 0.04]`。

2. **缺陷 A（真 bug）**：`best_of()` 用 `min()` 选最优超参。Python 的 `min` 遇 NaN
   行为依赖顺序——比较涉及 NaN 时恒为 False，所以**如果第一个候选就是 NaN，它会被永远保留**。
   已改为先过滤非有限值，并在一组候选全发散时显式报错。

3. **缺陷 B（真 bug）**：发散的结果被存成 `status="done"` + `val_loss=nan`，
   重跑时会被当作"已完成"跳过，**等于把这组配置永久判死**。
   现已改为：训练中一旦 loss/梯度非有限，立即早停并记 `status="diverged"`，
   重跑时会重新尝试。

4. 另有：B2 现在会把发散跑标注出来，不再把 nan 混进均值。

## 2026-11-21 排查（二）：KL 臂的 ε 扫参一直是无效的

**三个真 bug，都会让结论失真：**

1. **`RunConfig.tag` 漏了 `kl_eps`** —— 所有 ε 值共用同一个缓存文件名，
   于是扫参的第二个点起全部命中缓存、直接返回第一个 ε 的结果。
   实测：ε=1e-4 / 1e-3 / 1e-2 三个值得到**完全相同**的 val_loss，目录里只有 1 个文件。
   已把 `kl_eps`、`kl_every` 加入 tag。

2. **ε 的搜索范围偏小** —— 修好 bug 后测到 η ∝ √ε，原区间 [1e-4, 3e-3] 只对应
   η ≈ [0.012, 0.07]，而 Muon 的最优 lr 在 0.02 附近，等于 KL 臂大半时间在偏小的
   步长上被评判。已改为 [3e-5, 1.25e-4, 5e-4, 2e-3]，对应 η ≈ [0.006, 0.07]。

3. **扫参不打印实际 η** —— 由于 ε 的量纲不直观，之前无法判断两个臂的搜索范围是否可比。
   现在每个 KL 点都会打印 `实测η中位≈x`。

**为什么扫 ε 而不是 η 是正确的：** intentional updates 的定义就是"先指定结果、再反解步长"。
ε 是那个被指定的结果（每步把预测分布移动多少 nats），η 是派生量、每 20 步还会变。
直接调 η 就退化成普通的学习率调参，失去这个方法的立论。
代价是 ε 量纲不直观，所以必须同时报告换算出的 η，用来看搜索范围是否对齐。

**教训：** 缓存 key 必须覆盖所有影响行为的字段。这个 bug 不会报错、不会 NaN，
只会让扫参悄悄返回同一个结果——比崩溃更难发现。

## 2026-11-21 修订（三）：扩 ε 上界 + 修正 η 汇报

**1. ε 上界不够。** 在 384×6 上，global 臂 loss 随 ε 单调下降（5.71 → 5.61 → 5.31 → 4.89），
到 2e-3 还没到底，且 4.89 已经接近 Muon 的 4.90。故补齐两点：
`[3e-5, 1.25e-4, 5e-4, 2e-3, 8e-3, 3e-2]`（η 间距 √4 = 2 倍）。

**2. `实测η中位` 显示 0.0000 是个 bug。** 它取的是**最后一次**测量，而 cosine 日程那时
已把 ε 衰减到接近 0。改为记录 **sched 最大时的有效测量**，并换算回名义预算（sched=1）。
另有一个连带坑：step 0 没有动量，返回 `{"status":"no_momentum"}`，而它的 sched 恰好是 1.0，
会把后面所有有效测量挡住——现在只记录带 eta 的诊断。

修复后实测（小模型）：ε=1e-6→η=0.0015，1e-5→0.0047，1e-4→0.0148，1e-3→0.0468，
确认 η ∝ √ε；`kl_achieved_ratio = 1.0004`，校准精确。

**3. 旧缓存兼容。** 早先的缓存没有 `sched_seen` 字段，其 η 是无意义的 ~0，
所以扫参只在存在该字段时才打印 η，避免显示假数字。
